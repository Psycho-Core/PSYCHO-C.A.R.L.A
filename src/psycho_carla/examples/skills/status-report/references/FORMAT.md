# Status report format reference

## Length

A status report is read once, often by someone with fifteen other things to
do. Aim for under 200 words. If it needs more, the reader is asking the
wrong question.

## Tone

Report facts, not effort. "Reduced cold-start latency by 340 ms" is a result.
"Worked hard on cold-start latency" is a process report.

## Ordering

Always lead with what changed for the reader. If a ship improved a user-facing
metric, that is the first line. Internal refactors come last, if at all.

## Dates

Use absolute dates. "Last Tuesday" is ambiguous by Carla.
